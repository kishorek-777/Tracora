# /p2 — Masters

6 dev-days. Depends on P1. Rules 6, 7, 9 apply directly.

## Read

`docs/LLD.md`: field tables for Tracora Company through Tracora
Employee, plus the HRMS-owned / Tracora-owned field map. Nothing else.

## Build — backend

**Tracora Company** — `company_name` (primary key), `company_type`
(Select `Internal`/`External`, required, **no default** — rule 9 hangs
off this), `company_abbr` (required, **unique index**),
`company_address`, `source`, `hrms_company` (Data, text reference, never
a Link — rule 4).

**Tracora Branch / Tracora Department** — name, `company` (Link,
required), `source`, hrms reference. Controller `autoname()` producing
`{name} - {company_abbr}`.

**Tracora Location** — `location_name` (plain primary key, NOT
company-qualified), `address`, `latitude`/`longitude` (Float, precision
6, range-validated). `map_url` as a virtual field computing
`https://www.google.com/maps?q={lat},{lng}`.

**Tracora Employee** — controller `autoname()`: `EXT-.######` when the
company is External, otherwise the supplied code. Fields per the LLD.
- Branch/department required only when the company is Internal AND the
  record was entered by hand — a `validate()` check, not `reqd: 1`.
- Rule 9: `validate()` refuses any value in `date_of_birth`,
  `aadhaar_number`, `permanent_address` when the company is External.
- Read-only map applied in `onload` for `source = HRMS` records;
  `aadhaar_number` stays editable regardless of source. This is
  deliberate, not a sync gap: HRMS holds its own `custom_aadhaar_number`
  field, and Tracora's copy is entered independently for asset handover
  and is never read from or written to HRMS. The two are expected to
  differ over time — see the field-ownership note in `AGENTS.md`.
  `permanent_address` is a stock HRMS field and follows the normal
  HRMS-owned rule (read-only when `source = HRMS`).

## Build — UI

- **List views**: Company shows name, type, abbreviation — with type as
  an indicator (Internal green, External blue), because that distinction
  drives behaviour everywhere downstream. Employee shows code, name,
  company, status with a status indicator. Location shows name and
  address.
- **Employee form sections**: *Identity* (code, name, designation),
  *Organisation* (company, branch, department), *Contact* (mobile,
  email), *Personal* (DOB, Aadhaar, permanent address — collapsed by
  default, and `depends_on` hides the whole section when the company is
  External), *Status* (status, exit date, exit recorded in), *Source*
  (source, hrms reference — collapsed, read-only).
- **`map_url` renders as a clickable link with the label "Open in
  Maps"**, not a raw URL string in a field. A user opening a location
  wants a button, not a URL to copy.
- Empty state on the Location list invites the first location rather
  than saying "No Tracora Location found".
