# /p3 — HRMS integration

8 dev-days. Depends on P1, P2. Rules 3, 4, 6, 12 apply. **Highest-risk
phase in the build.** Do not compress the verification.

## Read

`docs/HLD.md` §6 for the model, `docs/LLD.md` integration section and
the `Tracora Sync Conflict` field table. Nothing else.

## Build — backend

`integrations/hrms.py`, every function wrapped in try/except (rule 3):

**`on_employee_change(doc, method)`** — HRMS `Employee` `after_insert`
and `on_update`:
1. Code absent in Tracora → find-or-create company, then branch and
   department, then the employee with `source = HRMS`. Order matters.
2. Exists, `source = HRMS` → update HRMS-owned fields only.
3. Exists, `source = Tracora`, values match → attach reference, flip
   source.
4. Exists, `source = Tracora`, values differ → write nothing, raise a
   `Tracora Sync Conflict`.
5. Exited, nothing outstanding → `Exited`.
6. Exited, assets or seats outstanding → `Pending Clearance`. Never
   block, never throw.
7. Exit reversed in HRMS → back to `Active`, but only if Tracora's exit
   came from HRMS. An Admin's manual exit is never undone by a sync.

**`on_employee_rename`** (`after_rename`) — match by `hrms_employee`,
not by old code. Rename the Tracora document. Never create a second.

**`on_hrms_delete`** (`on_trash`) — keep the record, clear the
reference, set `source = Tracora`. Never cascade.

Equivalents for Company, Branch, Department, plus `after_rename` on
Branch.

**`hooks.py`** — the `doc_events` block wiring these to HRMS doctypes.
This is the one legitimate `doc_events` use in this app: you are
hooking doctypes Tracora does not own.

**`Tracora Sync Conflict`** — `reference_doctype`, `reference_key`,
`conflict_type` (`Value mismatch`/`Subscriber failure`),
`hrms_reference`, `hrms_values` (Code/JSON), `tracora_values`
(Code/JSON), `conflict_status`.

**`bulk_import()`** — whitelisted, Super Admin only, **dry-run by
default**: reports what would change, writes nothing. A separate
explicit flag runs it for real. One-time migration tool, not a job.

## Build — UI

This phase produces the app's most neglected screen if you let it. A
conflict nobody can act on is a log line with extra steps.

- **Conflict list view**: reference key, record type, differing fields,
  status indicator (Open orange, Resolved green). Standard filter on
  status defaulting to Open, so the list opens as a work queue.
- **Conflict form shows both values side by side** — HRMS value and
  Tracora value per differing field, in two columns, aligned. Not two
  JSON blobs the user has to diff by eye. Add a *Resolve* button that
  marks it resolved after the person has edited the Tracora record.
- **Bulk import dialog**: a dry-run summary table — created, skipped,
  conflicted, with counts — and a clearly secondary *Run for real*
  button that only appears after a dry run has been viewed.
- Conflict count surfaces on the Tracora workspace as a link when
  greater than zero. Not a decorative number card; a link that reads
  "3 sync conflicts need attention" and disappears at zero.

## Verification — evidence required

Every one of these, demonstrated, in the walkthrough:

- Create an HRMS employee → matching Tracora employee, `source = HRMS`,
  chain created.
- Edit the HRMS mobile → updates in Tracora.
- Edit `aadhaar_number` on that Tracora record → still editable, and
  confirm the sync does NOT touch it (rule 9a) — HRMS's
  `custom_aadhaar_number` and Tracora's `aadhaar_number` are
  independent by design, not by omission.
- Edit `permanent_address` via HRMS → confirm it DOES sync to Tracora
  and becomes read-only there, same as any other HRMS-owned field.
- Rename the HRMS employee code → **same** record renamed, not a second
  created. Show the record count before and after.
- Delete the HRMS employee → Tracora record survives, source flips,
  fields become editable.
- Same code in both with different values → conflict created, neither
  record changed. Screenshot the side-by-side conflict form.
- **Force a subscriber to fail and show HR's save still succeeding.**
  This is the single most important test in the phase. If it is not
  demonstrated, the phase is not done.
- `bulk_import()` dry run → row counts identical before and after.
