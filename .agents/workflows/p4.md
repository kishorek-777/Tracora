# /p4 — Asset register

5 dev-days. Depends on P2. Rules 1, 5, 8, 10 apply.

## Read

`docs/LLD.md` Tracora Asset field table and the tag/serial namespace
note. Status and condition lists from FR-14/FR-15.

## Build — backend

**Tracora Asset** per the LLD. Points to watch:
- `asset_tag` set by `autoname()`, not typed into directly.
- `serial_no` unique **per brand**, not globally.
- `owner_company` and `holding_company` both required, separate (rule
  10).
- `branch` required only when `holding_company` is Internal.
- `assigned_to` and `assigned_on` present on the doctype but **not
  editable on the form** — P5 provides the only way to set them.
- `validate()`: reserved-prefix refusal for manual tags;
  cross-field uniqueness both directions (rule 8) — a candidate tag
  checked against every `asset_tag` AND every `serial_no`, and a
  candidate serial the same way.

## Build — UI

- **List view**: tag, name, brand, status indicator (per the colour
  table in `ui-conventions.md`), holder, location. Standard filters on
  status, company, location. This list is the app's home screen in
  practice — it should answer "what do we have and where is it" without
  opening anything.
- **Form sections**: *Identification* (tag mode, tag, name, brand,
  model, serial), *Ownership* (owner company, holding company, branch),
  *Location and custody* (location, assigned to, assigned on — the
  custody fields read-only with a hint that they are set by the Assign
  action), *Condition* (status, condition), *Labels* (label printed on,
  collapsed).
- **Tag mode drives the form**: when `Auto-generated` is selected, the
  tag field is hidden entirely rather than shown-and-disabled. Showing
  a field that will be filled by the system invites someone to type in
  it.
- Status and condition both visible in the form header area as
  indicators, since they are what a person opening an asset checks
  first.
- Empty state on the Asset list: "No assets yet. Register the first
  one." with the New button, not a bare "No Tracora Asset found".
