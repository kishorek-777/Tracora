# /p5 — Assignment and movement history

6 dev-days. Depends on P4. Rules 1, 2, 10, 14 apply. This phase builds
the mechanism rules 1 and 2 describe — treat it like P3.

## Read

`docs/LLD.md` Tracora Asset Movement field table and the `api.assign.*`
method table. `docs/PRD.md` flows: Assign, Unassign, Employee exit —
for the refusal conditions.

## Build — backend

**Tracora Asset Movement** per the LLD. `recorded_by` set server-side,
never from client input. `remarks` mandatory on `Unassign` and
`Exit Release`. Append-only guard per rule 2 — `validate()` throws when
the document already existed, `on_trash()` throws unconditionally, for
every role including Administrator.

**`api/assign.py`**:
- `assign_asset(asset, employee, reference)` — refuses when already
  assigned (naming the holder), when status is `Under Maintenance` /
  `Lost` / `Retired` (naming the status), when the employee is `Exited`
  or `Pending Clearance`. Otherwise sets custody and writes the
  movement in the same transaction.
- `assign_to_employee(employee, assets[], reference)` — same logic,
  list entry point. Must be indistinguishable in result.
- `unassign_asset(asset, location, remarks, condition, status)` —
  refuses blank remarks; returns the asset to a location; flags licence
  seats (stub with a TODO referencing FR-59 until P8).
- `transfer_ownership(asset, to_owner, reason)` — the only path that
  may change `owner_company`. Closes the gap P4 left open.
- `recover_asset(asset, remarks, condition)` — valid only from `Lost`.
- Every refusal names cause and fix (rule 14) — the server produces the
  string the user reads, so write it as user-facing copy, not a
  developer message.

**Delete guard** on `Tracora Employee.on_trash()` — refuse when the
employee appears in any movement.

## Build — UI

This is where Tracora stops being a table and becomes a ledger. Spend
the effort here.

- **Action buttons on the Asset form**, shown by status, absent when
  inapplicable rather than present-and-erroring:
  `In Store` → Assign, Print label.
  `Assigned` → Unassign, Send to maintenance, Print label.
  `Lost` → Recover.
  Any status → Transfer ownership (secondary group).
- **Assign dialog**: employee link with a live search, a reference
  field, a date defaulting to today. Company/branch/department of the
  chosen employee fill in read-only beneath the picker so the user can
  see they picked the right person before confirming.
- **Unassign dialog**: return location and remarks, remarks marked
  required and blocked client-side too — the server refuses it anyway
  (FR-51), but nobody should reach that error. Optional condition and
  status when the asset comes back damaged.
- **The movement history is the centrepiece of the Asset form.** Render
  it as a chronological list on the form's dashboard/connections area,
  newest first, each entry reading as a sentence a person understands:
  "Assigned to Priya Kumar — 12 Sep 2026 — by kishore.k". Not a raw
  child-table grid of foreign keys. Include the remarks inline, because
  the remark is the only record of *why*.
- **Employee form gains an *Assets held* section** listing current
  assets with tag, name and assigned date, plus an Assign assets button
  invoking the list entry point. Empty state: "No assets assigned."
- Refusal messages surface as Frappe error dialogs with the server's
  wording intact — do not wrap them in a generic "Operation failed".
