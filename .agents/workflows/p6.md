# /p6 — Maintenance

3 dev-days. Depends on P4, P5.

## Read

`docs/LLD.md` Tracora Maintenance Log field table. `docs/PRD.md`
Maintenance and repair flow.

## Build — backend

**Tracora Maintenance Log** per the LLD. `due_date` drives the
maintenance-due reminder in P9 — without it that reminder can never
fire, so treat it as meaningful, not optional decoration.

- Opening a log sets the asset to `Under Maintenance` and writes a
  `Maintenance Sent` movement. The asset keeps its holder but cannot be
  reassigned — P5's status check already enforces this; confirm it
  still holds rather than reimplementing it.
- Closing requires `condition_on_return`, returns the asset to its
  previous status, writes `Maintenance Returned`, updates condition.
- `Beyond Repair` routes to `Retired` instead of back to service.

## Build — UI

- **Send to maintenance** is a dialog from the Asset form (added in
  P5's button set): reason, vendor, date sent, expected return. Expected
  return carries a description explaining it drives reminders — the one
  field users will skip otherwise.
- **An open maintenance record shows as a banner on the Asset form**:
  "At Dell Service since 4 Sep — expected back 18 Sep", with a Close
  maintenance button. Not buried in a connections tab. An asset in a
  repair shop is the state most likely to be forgotten.
- **Close dialog** requires condition on return, and defaults status
  back to the pre-maintenance value rather than making the user
  remember it.
- Maintenance list view: asset, vendor, date sent, expected return,
  status indicator (Open orange, Closed green, Beyond Repair grey).
  Standard filter defaulting to Open, so the list is a work queue.
- Overdue returns — expected return date in the past, still open —
  show a red indicator. This is free information the list should not
  hide.

## Verification — evidence required

- FR-18 — open a log, asset status changes, movement written.
- Assigning that asset while maintenance is open is refused.
- Closing without `condition_on_return` refused.
- Close normally — status restored, `Maintenance Returned` movement
  exists, condition updated.
- `Beyond Repair` → asset `Retired`, history intact.
- Exit an employee holding an asset that is `Under Maintenance` — still
  counts as outstanding. Test explicitly; do not assume P3's check
  reads status correctly.
- Screenshot of the open-maintenance banner on an asset form.
- Screenshot of the maintenance list with one overdue row showing red.
