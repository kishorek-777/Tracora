# /p7 — Tags, QR codes and label printing

5 dev-days. Depends on P4. Rule 8 applies. Read the label section of
`.agents/rules/ui-conventions.md` — the label is a physical object and
the constraints there are functional, not stylistic.

## Read

`docs/LLD.md` asset tags and labels section, print format notes,
FR-41 to FR-49, FR-66, FR-67.

## Build — backend

- Confirm P4's tag mode and `autoname()` are correct before extending.
- `tags/qr.py` — `qr_base64(tag)` encoding the **bare tag string**.
  No URL, no employee, no company, no personal data, ever. Add `qrcode`
  to the app's `requirements.txt`; do not assume the bench has it.
- `api/labels.py` — `get_label_data(assets[])` serving both single and
  batch printing. Batch renders one document containing every label,
  not one file per asset.
- Every print writes a `Label Reprint` movement and updates
  `label_printed_on` — including the first print.

## Build — UI

**The label print format.** 50 × 25 mm from Settings. Layout:

```
┌──────────────────────────────┐
│  ███████                     │
│  ██ ▄▄ ██   TRC-000042       │   QR ≥15mm, quiet zone intact
│  ███████    Dell Latitude    │   tag: large, mono, disambiguated
└──────────────────────────────┘   name: smallest, truncated
```

- Tag number in the monospace face from `ui-conventions.md`, large
  enough to read and type from without a scanner. This is the fallback
  when the QR is scratched — size it for that job, not for balance.
- No logo, no border decoration, no colour. Equipment, not stationery.
- Test the actual printed size, not just the screen preview. A print
  format that looks right in a browser and comes out at 70% scale is
  the normal failure here.

**Batch printing UI**: from the Asset list, select rows → Print labels.
A dialog showing the count and a preview of the first label, then one
combined document. Selecting fifty assets must not produce fifty tabs.

**On the Asset form**: Print label button (added in P5's set). If
`label_printed_on` is set, the button reads "Reprint label" and shows
the last print date beside it — reprinting is legitimate but should be
a visibly deliberate act.

## Verification — evidence required

- FR-44 — decode a **printed** label with a phone scanner; show it
  returns the bare tag and nothing else.
- FR-45 — photograph of a printed label showing the tag number legible
  without scanning.
- FR-46 — a printed label measured against a ruler at 50 × 25 mm, QR at
  least 15 mm. Photograph it. Screen previews do not count.
- FR-47 — twenty assets selected, one document produced containing
  twenty labels.
- FR-48 — reprint twice: tag unchanged, no new asset, two `Label
  Reprint` movements.
- FR-43 — a manual tag starting with the reserved prefix still refused.
