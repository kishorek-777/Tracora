## Architectural Notes & Deliberate Deviations

- **Software Licence Date Model Redesign (Contract Update for Phase 9)**:
  - **Schema changes**: Removed `licence_renewal_date`, `payment_date`, and `last_paid_on`. Added `licence_start_date` (Date, optional) and `next_renewal_date` (Date, read_only: 1). Repurposed `last_renewed_on` description as "Date the scheduler last recalculated the renewal date".
  - **Calculation Logic**: Replaced manual roll-forward buttons and endpoints (`roll_forward_renewal`, `roll_forward_payment`) with pure deterministic projection `calculate_next_renewal(start_date, cycle, reference_date=None)` in `tracora/licences/roll_forward.py`.
  - **Daily Scheduler**: Registered `recalculate_next_renewal_dates()` in `tracora/licences/status.py` under `scheduler_events["daily"]` in `hooks.py`. It computes `next_renewal_date` for every licence with a set `licence_start_date` and updates `last_renewed_on = today()` when a renewal checkpoint is advanced.
  - **CRITICAL Phase 9 Interface Contract**: Phase 9's reminder scheduler must monitor **`licence_expiry_date` and `next_renewal_date` only**. Fields `payment_date` and `licence_renewal_date` are removed.
- **Deliberate Deviation from FR-59 Wording (Asset Deletion)**: 
  The PRD FR-59 text describes flagging seats when an asset is deleted. However, in Tracora, `Tracora Licence Seat.device` is a required Link field pointing directly to `Tracora Asset`. If an asset were deleted, linked child seats would point to a non-existent foreign key or trigger cascade errors. Therefore, **asset deletion is implemented as a hard block** (`frappe.throw(ValidationError)`) in `TracoraAsset.on_trash()`, requiring administrators to explicitly release or reassign attached seats before deleting the hardware asset. (Documented in `tracora_asset.py#on_trash`).
- **Grouped-Save Concurrency Guard**: 
  `flag_active_seats_for_device()` groups seats by parent licence before saving, ensuring `.save()` is called exactly once per unique parent licence, eliminating `TimestampMismatchError` race conditions.
- **Unassigned Licence Renewal**: 
  A 0-seat (`Unassigned`) licence with `licence_start_date` set calculates `next_renewal_date` cleanly and preserves `Unassigned` status (verified by `test_roll_forward_unassigned_licence_allowed`).
- **Seats API Authorization**:
  `get_installed_licences(asset)` validates permissions on `Tracora Software Licence` and `Tracora Asset`, rejecting unauthorized users with `frappe.PermissionError`.

## Build — backend

**Tracora Software Licence** per the LLD, including `licence_type`
(`User licence` / `Device licence`) and `licence_status`
(`Active`/`Unassigned`/`Expired`, set by the P9 job, not by hand).

**Tracora Licence Seat** (child) — `user` required on a User licence,
optional on a Device licence; `device` always required.
`validate()` refuses a duplicate user-and-device pair.

**Next Renewal Calculation** (replaces old manual roll-forward) — pure mathematical function
`calculate_next_renewal(start_date, cycle, reference_date=None)` and daily job
`recalculate_next_renewal_dates()` in `status.py`.

when a device is unassigned, retired, disposed or deleted. Go back into
P5's `unassign_asset` and P4's retire/delete paths and wire it properly
now.

## Build — UI

- **Licence form**: *Licence* (software name, licence name, type,
  company), *Dates* (licence_start_date, licence_expiry_date, next_renewal_date) grouped
  together, *Seats* (the grid), *History* (last renewed — read-only, collapsed).
- **Licence type changes the seats grid**: on a Device licence the user
  column is optional and visibly so; on a User licence it is required.
- **Seat status indicators in the grid** — Active green, Flagged
  orange, Released grey.
- **A flagged seat raises a banner on the licence form**: "2 seats need
  attention — the device was unassigned." with the seats listed.
- **Licence list view**: software, type, expiry, next renewal date, seat count, status
  indicator.
- **Expiry proximity & Renewal proximity**: Days remaining indicator and color coding.
- On the Asset form, seats installed on that device appear in the
  connections area via `get_installed_licences(asset)`.
