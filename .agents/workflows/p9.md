# /p9 — Reminders

**Status**: REVISED DRAFT PLAN (Pending Final Approval)  
**Effort**: 6 dev-days. Depends on P8.

## Architectural Notes & Decisions

1. **Monitored Date Fields (Definitive Scope)**:
   - Phase 9 monitors **strictly two date fields** on `Tracora Software Licence`:
     1. `licence_expiry_date` → `reminder_type = "Licence Expiry"`.
     2. `next_renewal_date` → `reminder_type = "Licence Renewal"`.
   - `warranty_expiry_date` is **definitively OUT of scope** for Phase 9.
   - `payment_date` and `licence_renewal_date` are deleted from the schema and not referenced.
   - The `reminder_type` Select field options on `Tracora Reminder Log` are strictly:
     ```
     Licence Expiry
     Licence Renewal
     ```

2. **Overdue Handling Scoped to `licence_expiry_date` Only**:
   - `recalculate_next_renewal_dates()` runs before reminders and always projects `next_renewal_date` to >= today. Therefore, `next_renewal_date < today` is mathematically unreachable in normal scheduled runs.
   - Overdue evaluation applies **strictly to `licence_expiry_date`** (`diff < 0`), fulfilling FR-89: if an expired licence is imported or lapses, it dispatches exactly one overdue notice (`days_before = -1`) and records a log entry so it is never silent and never repeated.
   - **`diff >= 0` guard on `next_renewal_date`**: Purely defensive code. In normal daily operations, `recalculate_next_renewal_dates()` and `TracoraSoftwareLicence.validate()` guarantee `next_renewal_date >= today()`. The `diff >= 0` guard is retained as a harmless safety check for isolated test runs, direct script calls, or raw database imports where `recalculate_next_renewal_dates()` has not yet executed.

3. **Literal Licence Query Filter (No Expired Exclusion)**:
   - The job evaluates all licences regardless of status (including `licence_status == "Expired"`) so that past-due expiries trigger their one-time FR-89 overdue notice.
   - Literal query:
     ```python
     licences = frappe.get_all(
         "Tracora Software Licence",
         fields=["name", "software_name", "licence_name", "licence_expiry_date", "next_renewal_date", "licence_status"]
     )
     ```
   - No status exclusion filter. Blank dates are handled in code (`if not lic.licence_expiry_date: ...`).

4. **Recipient Resolution & Enabled Filter**:
   - Queries users holding role `Tracora Super Admin` or `Tracora Admin` and explicitly filters on `enabled = 1`:
     ```python
     admin_users = frappe.get_all(
         "Has Role",
         filters={
             "role": ["in", ["Tracora Super Admin", "Tracora Admin"]],
             "parenttype": "User"
         },
         pluck="parent",
         distinct=True
     )
     active_recipients = frappe.get_all(
         "User",
         filters={
             "name": ["in", admin_users],
             "enabled": 1,
             "user_type": "System User"
         },
         pluck="email"
     )
     ```
   - If `active_recipients` is empty, the job logs a warning, updates `last_reminder_run`, and returns cleanly (triggering the FR-90 health warning on the workspace).

5. **Individual Emails Per Recipient (No Shared Batch Digest)**:
   - Each qualifying recipient receives an **individual email**.
   - Each recipient has an isolated row in `tabTracora Reminder Log`. If sending to one recipient fails (e.g. SMTP rejection), it is marked `Failed` without blocking dispatch to other recipients.
   - Satisfies the unique constraint: `(reference_doctype, reference_name, reminder_type, due_date, days_before, recipient)`.

6. **Daily Job Pipeline Order**:
   - Order registered in `hooks.py` `scheduler_events["daily"]`:
     1. `tracora.licences.status.recalculate_next_renewal_dates` (advances renewal dates).
     2. `tracora.licences.status.mark_expired_licences` (marks expired statuses).
     3. `tracora.reminders.scheduler.run_daily_reminders` (evaluates milestones, dispatches emails, records logs).

## Build — backend

### 1. `Tracora Reminder Log` DocType
- **Fields**:
  - `reference_doctype` (Data, required) — `Tracora Software Licence`
  - `reference_name` (Data, required) — e.g. `TSL-000001`
  - `reminder_type` (Select, required) — `Licence Expiry\nLicence Renewal`
  - `due_date` (Date, required) — snapshot of `licence_expiry_date` or `next_renewal_date`
  - `days_before` (Int, required) — milestone integer (`30`, `15`, `7`, `2`, `1`, `0`, or `-1` for Overdue)
  - `recipient` (Data, required) — recipient email address
  - `sent_on` (Datetime, required) — dispatch timestamp
  - `delivery_status` (Select, required) — `Queued`, `Sent`, `Failed`
  - `error_message` (Small Text, optional) — error details if send fails
- **Database Constraint**:
  - Unique index across `(reference_doctype, reference_name, reminder_type, due_date, days_before, recipient)`.
- **Controller Immutability (`tracora_reminder_log.py`)**:
  - Append-only guard: `validate()` blocks updates to existing records, `on_trash()` blocks deletions for all users (including `Administrator`) per NFR-03.
  - Permissions in JSON: `Tracora Super Admin` and `Tracora Admin` have Read permission only.

### 2. `reminders/scheduler.py` — `run_daily_reminders()`
1. Read `reminder_lead_days` from `Tracora Settings` (default `"30,15,7,2,1,0"`), parsed into a set of integers.
2. Resolve `active_recipients` (enabled System Users with Tracora Admin roles). If empty, finish run and exit.
3. Fetch all licences via `frappe.get_all("Tracora Software Licence", fields=["name", "software_name", "licence_name", "licence_expiry_date", "next_renewal_date", "licence_status"])`.
4. Loop through each licence:
   - **`licence_expiry_date`**:
     - If unset → skip.
     - Calculate `diff = frappe.utils.date_diff(lic.licence_expiry_date, frappe.utils.today())`.
     - **FR-89 Overdue**: If `diff < 0`:
       - For each recipient: check if log exists for `(lic.name, 'Licence Expiry', lic.licence_expiry_date, -1, recipient)`.
       - If not logged: dispatch overdue notice, insert log row (`days_before = -1`).
     - **Upcoming Milestone**: If `diff in reminder_lead_days`:
       - For each recipient: check if log exists for `(lic.name, 'Licence Expiry', lic.licence_expiry_date, diff, recipient)`.
       - If not logged: dispatch reminder, insert log row (`days_before = diff`).
   - **`next_renewal_date`**:
     - If unset → skip.
     - Calculate `diff = frappe.utils.date_diff(lic.next_renewal_date, frappe.utils.today())`.
     - **Upcoming Milestone**: If `diff in reminder_lead_days` and `diff >= 0`:
       - For each recipient: check if log exists for `(lic.name, 'Licence Renewal', lic.next_renewal_date, diff, recipient)`.
       - If not logged: dispatch renewal notice, insert log row (`days_before = diff`).
5. Stamp `Tracora Settings.last_reminder_run = frappe.utils.now_datetime()`.

### 3. Settings Validation (`tracora_settings.py`)
- Validate `reminder_lead_days` format: ensure positive/zero comma-separated integers. Throw `frappe.ValidationError` if invalid.

## Verification — evidence required

1. **FR-26 (Upcoming Milestones)**:
   - Create a licence with `licence_expiry_date = add_days(today(), 30)`. Run `run_daily_reminders()`.
   - Assert log row exists for `(licence.name, 'Licence Expiry', expiry_date, 30, recipient)`.
   - Update date to `add_days(today(), 29)`. Run `run_daily_reminders()`.
   - Assert zero new log rows generated (29 is not in lead days).
2. **FR-89 (Overdue Past Expiry)**:
   - Create a licence with `licence_expiry_date = add_days(today(), -10)`. Run `run_daily_reminders()`.
   - Assert exactly one log row created with `days_before = -1` per recipient.
   - Run `run_daily_reminders()` a second time on the same or subsequent day: assert zero duplicate log rows created.
3. **FR-63 / FR-65 (Dynamic Date Shifts & Stale Log Isolation)**:
   - Create a Monthly licence with `next_renewal_date = today()` (cycle checkpoint due today).
   - Run `run_daily_reminders()`: assert log row created for `due_date = today()`, `days_before = 0`.
   - Simulate checkpoint advancement: call `recalculate_next_renewal_dates()`. The licence's `next_renewal_date` advances forward to `today() + 1 month`.
   - Set reference/system context or simulate 7 days before the new renewal date (`next_renewal_date = add_days(today(), 7)`).
   - Run `run_daily_reminders()`:
     - Assert that the historical log row for `due_date = today()` does NOT prevent the new reminder.
     - Assert a new log row is created for `due_date = new_date`, `days_before = 7`.
     - Assert total logs for this licence = 2 (one per distinct due date cycle).
4. **Idempotency**:
   - Run `run_daily_reminders()` twice consecutively on identical state: assert zero additional emails or log rows created.
5. **FR-90 (Health Alert)**:
   - Set `Tracora Settings.last_reminder_run = add_days(now_datetime(), -3)`: assert workspace warning helper returns `is_stale = True` with humanized time.
   - Run `run_daily_reminders()`: assert `last_reminder_run` updates to current timestamp and `is_stale = False`.
6. **Append-Only Immutability (NFR-03)**:
   - Attempt to edit any field on an existing `Tracora Reminder Log`: assert `ValidationError` thrown.
   - Attempt to delete a `Tracora Reminder Log` (even as `Administrator`): assert `ValidationError` thrown.
7. **Role & Enabled Filtering**:
   - Disable all admin users (`enabled = 0`): run `run_daily_reminders()`.
   - Assert job completes without uncaught exception, zero emails dispatched, and workspace alert flags `no_recipients = True`.
8. **Test Suite**:
   - `tracora.tracora.tests.test_reminders` with all tests passing. Full suite `bench --site mysite.local run-tests --app tracora` runs with 0 failures and 0 errors.
